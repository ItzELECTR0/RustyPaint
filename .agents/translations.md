# Translations

`res/i18n/<tag>.ftl` is the whole catalogue, one Fluent file per locale, embedded with
`include_str!`. `en-GB` is the source: it is written first, everything else is a translation of it,
and it is the fallback for any locale with no catalogue of its own.

`crate::i18n` owns both the engine and the accessor table, and nothing in it reaches into `ui`. That
placement is not cosmetic. The examples in `crates/rustypaint/examples/` pull individual `src/`
modules in by `#[path]` rather than linking the binary, so a module they include cannot depend on
the wider interface. `paint/`, `doc/`, `text/`, `select/` and `ui/theme/` are all in that set, and
all of them name things the user reads.

## Reaching a string

`i18n::save()` and friends are generated by the `catalogue!` macro in `i18n/catalogue.rs`, one
function per message that takes no arguments. A key that is not in the catalogue is a compile error
rather than a label that silently renders as its own key.

Messages that take arguments get a hand-written wrapper in the same file, because the argument names
are part of the contract:

```rust
pub fn canvas_size(width: u32, height: u32) -> String {
    tr!("canvas-size", width = width.to_string(), height = height.to_string())
}
```

Numbers are passed as strings that Rust has already formatted, so the output stays byte-for-byte
what it was before any of this existed. `$count` in `recovery-body` is the one exception: it is a
real number because Fluent needs one to pick a plural form.

`i18n::lookup(key)` takes a key directly, for the places a `const` table cannot call a function.
`sidebar::TABS` and `canvas::RESOLUTIONS` both hold keys for that reason, and resolve them where
they are drawn. It is named `lookup` rather than `text` because the accessors are re-exported
alongside it, and `text` is a message of its own; a key whose accessor would collide with `lookup`,
`format` or `init` has to be renamed instead.

## Adding a message

Add it to every file in `res/i18n/`, then add the accessor. `every_catalogue_defines_the_same
_messages` fails on a locale that is missing one, and `every_message_is_reachable_from_the_code`
fails on a catalogue entry no accessor names, so drift in either direction is caught.

## Adding a locale

Add the `.ftl`, then one `catalogue!` line in `i18n/mod.rs` and one `Language` variant. Negotiation
already handles the rest: exact tag, then any catalogue sharing the language, then the source. The
`Language::name` for a new locale is its own endonym and stays untranslated, the way a language list
is normally written.

## A plural form the rules get wrong

Romanian wants `de` before the noun from 20 up, and CLDR says that is `few` below 20 and `other`
from 20, wrapping every hundred: 101 is `few` again, because the rule is `n % 100 = 1..19`.
`intl_pluralrules` 7.0.2 compiled that rule as `i` in `2..=19` and lost the modulo, so 101 to 119,
201 to 219 and so on land in `other` and read "101 de documente" instead of "101 documente".

`recovery-body` is the only message with a plural at all, and it counts documents recovered after a
crash, so the wrong band is not reachable in practice. Left alone rather than worked around, because
the workaround would be a hand-rolled selector in the catalogue that goes stale the moment the crate
is fixed.

## What is deliberately not translated

- History labels in `Document::commit`. They are stored in the document, so translating them at
  commit time would bake in whatever language was active and leave the list stale after a switch.
  Nothing displays them yet; the history flyout should translate them at render time when it lands.
- Config file values, file extensions, and `expect` messages. None of them are read by a user.

## Choosing the locale

`Language::Auto` reads `sys_locale::get_locale()` once at startup. A resolved catalogue is built on
first use and cached in a `OnceLock` per locale, so `i18n::text` is a map lookup with no locking and
returns `&'static str` borrowed from that cache. Switching languages moves an atomic index; the
catalogue left behind stays built, which is why switching back is free.

Fluent's directionality isolation is turned off. It wraps every placeable in U+2068/U+2069, which is
right for prose and wrong for a button label.
